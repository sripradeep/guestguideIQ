# External Dependency Map — Backend Services for GuestGuideIQ

No external team, partner, or third-party approval currently gates any Bolt — this is a single-session, AI-only build with no external hand-offs. Four decisions remain open from earlier stages, though, and each is internally owned rather than blocked on an outside party. Per Q5 in `delivery-planning-questions.md`, they're tracked here anyway: an internally-owned open decision can still block a Bolt's *full* completion, and naming it now prevents it from being rediscovered mid-Bolt.

| Gating Item | Owner | Blocks | Fallback if It Slips |
|---|---|---|---|
| Events data source (`requirements.md` OQ2/FR6.4) — third-party events API, web monitoring, manual feed, or a mix | This team/session (no external party) | Bolt 5's event *ingestion* half only — the lifecycle/expiry half (US4.2's expiry/dedup logic) does not need the source chosen, per `domain-design/components.md`'s note that these are separate concerns | Build and demo Bolt 5's lifecycle/expiry logic against manually-entered test events; wire the real ingestion source once chosen, without touching the lifecycle logic |
| LLM provider and prompt-grounding approach (`requirements.md` OQ3) | This team/session (no external party) | Bolt 7 (Itinerary Chat) entirely — the endpoint's request/response shape depends on this choice (streaming vs. single response, per `contract-summary.md`'s Open Questions) | None available — Bolt 7 cannot meaningfully start until this is decided; flag as a hard blocker to resolve before Bolt 7 begins, not during it |
| Billing provider and plan structure (`requirements.md` OQ1) | This team/session (no external party) | Only the *payment-processing* half of Bolts 3's US1.7/US1.8 — the capability to create/track a subscription's status is not blocked | Build and demo Bolt 3 with subscription status tracking against a stub/mock payment result; wire the real billing provider once chosen |
| `admin-api` ↔ `backend-api` network/auth isolation mechanism (`contract-summary.md`'s Open Questions; the human's stated top concern, Q6) | This team/session (no external party) | Bolt 1's Definition of Done explicitly, since the walking skeleton does not consider itself complete with this purely conceptual | No fallback — per `risk-and-sequencing-rationale.md`, this is deliberately pulled into Bolt 1 rather than deferred, precisely so it cannot slip past the first Bolt |

## Hosting/Runtime Platform

`requirements.md` C3 leaves the hosting platform explicitly open (not committed to AWS despite the original marketing-site spec naming it as a likely eventual choice) and C4 leaves the backend language/framework/database undecided. Neither blocks any specific Bolt in this plan — every Bolt's Definition of Done is expressed in terms of behavior, not implementation technology — but both must be resolved before `infrastructure-design` and `code-generation` can proceed for Bolt 1. This is a `domain-design`/`infrastructure-design`-stage decision already tracked there, restated here only to confirm it does not silently gate Construction's first Bolt.
